# X 12.17.0 Download Fix Verification

**Date**: 2026-08-18
**Context**: After X auto-updated from 12.13.0 to **12.17.0-release.0 (312170000)**, the tweet download feature appeared broken ("seems after update X App, the download not work"). This documents the diagnosis, the fix, and the verification.

---

## Diagnosis

1. **Hooks init fine on 12.17.0** — all hooks (`MainActivityHook`, `ShareMediaHook`, `OkHttpFilterHook`, …) attach; `com.x.android.main.MainActivity` unchanged; the Android-16 result-delivery chain (hooked in the previous session) still matched (`com.twitter.app.common.base.g`, `androidx.fragment.app.y`).
2. **Ad filter + media capture work on 12.17.0** — a fresh process with a network fetch logs `captured media for tweet …` and `removed 7 promoted item(s)` exactly as on 12.12/12.13. The response structure (`tweet_results`, `media_entities`, `ApiImage`/`ApiVideo`) is unchanged.
3. **Real cause 1 — empty media cache on first launch**: X serves the home timeline from cache after an update; no network fetch → no response passes through the filter → no media captured → share trigger finds nothing → no dialog. Once any timeline/detail fetch happens, capture resumes.
4. **Real cause 2 — module broken on device, not in code**: the debug keystore lives under `ANDROID_USER_HOME` (`E:\Temp\Android\.android\debug.keystore`), and a temp cleanup regenerated it → new signature → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. After uninstalling the module, its **LSPosed scope was silently wiped** (`scope ls` → `[]`), so the module enabled but never injected. Restoring the scope fixed injection:
   ```
   /data/adb/lspd/cli scope add icu.nullptr.twifucker com.twitter.android/0
   ```
5. **Verification (end-to-end, 12.17.0)**: share → "Share via…" → BACK → `ShareMediaHook: pending download for tweet … (2 items)` → "Download or Copy" dialog with `1 · Image` / DOWNLOAD ALL / DISMISS. User confirmed the save works.

## Gotchas for future sessions

- **Debug keystore location**: `ANDROID_USER_HOME=E:\Temp\Android\.android` on this machine. If temp is cleaned, the debug key regenerates → signature mismatch on `install -r`. Fix: `adb uninstall icu.nullptr.twifucker && adb install …` (module prefs live inside X's data dir, so nothing is lost) **and** re-add the scope (see above), then re-enable:
  ```
  /data/adb/lspd/cli modules enable icu.nullptr.twifucker
  ```
- **`lspd cli` commands**: `modules ls --json` (not `list`), `scope ls/add/rm/set <pkg> <app>/<user>`.
- **`install -r` does not wipe scope; `uninstall` does.**
- **First launch after X update**: timeline comes from cache → empty media cache → download appears dead until the first network fetch. Not a bug — scroll to trigger a fetch.
- **adb over wifi can hang**: `adb kill-server && adb start-server && adb connect pixel6a:5555` recovers it.
- **Gradle cache corruption** (`Could not read workspace metadata`): delete `$GRADLE_USER_HOME/caches/8.9/transforms` + `kotlin-dsl` and rebuild.
- **APK cert check**: `keytool -printcert -jarfile` fails on v2-only signatures ("不是已签名的 jar 文件"); use `apksigner verify --print-certs` instead.
